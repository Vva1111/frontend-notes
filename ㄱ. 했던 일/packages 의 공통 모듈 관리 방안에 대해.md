## 모노레포의 공통 모듈 관리 방안

- **방안 1. apps/ 내부의 각 app이 모듈에 렌더링 될 모든 정보를 가지고 있고, 공통 모듈은 주입만 받는 방식 — 앱에서 의존성을 주입하는 예시**
	- apps/ 내부의 앱들이 모든 설정, store, api 요청 권한을 가지고 있고
	- packages/ 의 특정 모듈에 app 에 종속되는 정보를 주입해서 packages/ 내부의 공통 모듈들은 app 에 대한 정보를 몰라도 되게 하는 것이 목표
	- props, adapter, provider/inject 또는 명시적인 상태 접근 인터페이스를 사용해 앱에 종속되는 정보를 공통 모듈에 전달할 수 있다.
	- 위 방법은 복잡도가 높아지지만 공통 모듈이 app의 정보를 몰라도 된다는 점에서 앱 의존성을 분리하는 방식
	- 위 방식은 store state/action, api 등 공통으로 사용할 UI 값들 외에는 모두 app이 가지고 있어야 한다.

- **방안 2. 공통 기능 모듈이 store state/actions, api를 관리하는 방식**
	- 이 방식은 같은 기능을 공유하는 앱 사이에서 UI, store state/actions, API 요청 방식의 차이가 적을 때 오히려 비용은 적게 들고 개발도 쉬운 방향으로 진행할 수 있다.
	- 공통 모듈에 필요한 앱별 설정을 구성하고 각 앱의 진입점에서 해당 설정을 공통 기능 모듈에 전달한다. 실제 제품명이나 조직 구분 대신 필요한 기능과 옵션으로 설정을 표현한다.
	- config에 앱별로 구별해서 적용해야 할 정보가 테이블 칼럼, api 엔드 포인트, 파라미터 정도인 경우 해당 방식이 합리적이라고 할 수 있다.
